# 사운드·명상·선택 상태·물고기 출현 안정화

## 기준과 변경 파일

기준 소스는 GitHub `main`의 `f02614a`이다. 원본 음원 25개와 내장 귀뚜라미·빗소리를 보존했다. 물고기는 사용자가 확인한 대로 **현재 연못 배치·획득 확률을 유지하고 공통 출현 빈도만 1.5배** 높였다. 최신 소스에는 별도의 히나 연못 1.5배 확률 보정이 연결돼 있지 않았으므로 임의의 추가 보정은 만들지 않았다.

## 1. 소리 원인과 전체 호출 경로 정리

`tools/generate_sounds.py`의 `rustle()` 합성이 여러 WAV에 재사용되고 있었다. 단순히 `step` 재생만 끄면 다른 행동 파일에 들어 있는 짧은 잡음이 남는 구조였다. 또 기존 공통 클릭 분류기는 버튼 이름의 `제작/craft`를 제작 **행동** 소리로, `인벤토리`를 잡음이 든 inventory 파일로 연결했다.

| 사운드 ID/파일 | 확인된 호출/내용 | 수정 |
|---|---|---|
| `step`, 발걸음 별칭 | 공통 캐릭터 이동 콜백 | 중앙에서 차단, 자산 보존 |
| `inventory` | 잡음 합성 파일/기존 클릭 분류 | 원본 재생 차단. 실제 UI 열기·닫기는 `ui.wav`로 복구 |
| `water` | 마시기 버튼·실제 갈증 회복·완료 대사 | 중앙 차단, 모든 기존 호출은 안전하게 무음 |
| `wood`, `craft` | 나뭇가지·제작·제작 버튼의 잘못된 텍스트 분류 | 중앙 차단. 제작 메뉴에는 공통 UI 소리만 사용 |
| `rustle`, `wash` | 같은 짧은 잡음 합성 계열의 환경/행동 파일 | 공통 잡음 재생 차단, 파일·호출 코드 보존 |
| `eat` | 기존 파일에 잡음이 함께 들어 있음 | 기존 `eat.wav` 보존, `eat-start.wav`로 연결 |
| `fish` | 잡음과 짧은 음색이 섞여 있음 | 기존 파일 보존, 동일 음색의 `fish-clean.wav`로 연결 |
| `fireAmbient` | 모닥불 주변 주기적 반복 타닥거림 | 중앙 차단. 점화/연료/불 유지/시각 로직 유지 |
| `fire`, `cook`, 비·벌·새·부엉이 등 | 별개의 고유 효과/환경음 | 기존 음원·볼륨 유지 |
| `berry`, `animal` | 열매·야자잎 및 토끼 | 기존 파일 보존. 실제 채집/토끼 획득 경로에 연결 |

- 원본 파일/생성기 코드는 삭제하지 않는다. 강제 재생 API로 호출해도 차단된 ID는 재생되지 않는다.
- 열매·야자잎은 기존 실제 아이템 획득 표시 경로를 공유한다. 토끼는 공통 `rabbitCaptureHold()`와 히나의 기존 수동 관찰 완료 지점에서 정상 음원을 재사용한다.
- UI는 버튼 텍스트로 소리를 추측하지 않는다. 공통 observer가 기존 패널의 표시·숨김·하위 메뉴 상태를 비교하고 `playUITransition()` 한 곳에서 숙련도와 같은 `ui.wav`를 사용한다. 늦게 만들어지는 프로필 창도 등록한다.
- 한 포인터/키 입력에서 부모 닫기→자식 열기가 이어져도 공통 입력 토큰으로 중복음을 막는다. 단순히 눌렀지만 상태가 바뀌지 않은 UI에는 소리를 내지 않는다.
- 열매 먹기는 `CharacterAnimation.eat()`가 실제 거래/애니메이션을 받아들인 직후 소리를 낸다. 재료 없음·진행 중 중복 클릭은 거부하고, 완료 시 아이템 소비/허기 회복 지점에서는 같은 소리를 다시 내지 않는다.

## 2. 위협 의지력 감소 경고

공통 `threatWillLossSound(character, source, before, after)`가 뱀·곰의 **실제 감소 지점**에서 호출된다. 0 이하로 고정된 의지력, 감소 없음, 일반 야간 감소에는 재생하지 않는다. 현재 관찰 캐릭터에 대해 공통 2.5초 실제 시간 쿨다운을 사용하므로 다른 종류의 위협이 겹쳐도 중복 경고가 반복되지 않는다. 향후 생물 ID는 공통 source 집합에 추가할 수 있다.

기존 뱀 진입 -30, 곰의 거리별 초당 감소율과 판정식은 변경하지 않았다.

## 3. 명상 복구와 기존 밸런스

발견된 기존 구현은 `v504Meditation`이다. 기본 버튼은 생성만 되고 DOM에 붙지 않았으며, 유일한 대체 진입은 모닥불 hover/touch 하위 아이콘이었다. 다은은 수동 모드에서만 시작하도록 제한돼 있었다.

- 기존 버튼을 화면에 복구하고, 켜진 모닥불 7m 이내·깨어 있음 조건에서 PC/모바일에 표시한다. 다은의 기존 안전한 앉기 위치, 탈진 잠금 및 가방 없이 생선을 들고 있을 때의 제한을 유지한다.
- 공통 시작/종료/틱과 캐릭터 레지스트리의 위치·상태·모닥불 참조를 사용한다. 히나·다은 모두 같은 타이머를 쓰며, 기존 **게임 내 25분(1200초 하루 기준 20.833초) 후 의지력 +6, 1회 지급**을 유지한다.
- 기존 앉기 자세/회복 함수를 재사용하고 카메라를 빼앗지 않는다. 히나는 명상 시작 전 생리 상태를 유지하여 별도의 지속 회복률을 추가하지 않는다. 시작한 실제 행동이 끝날 때까지 AI 이동을 일시 보류하되 자동 모드 자체를 바꾸지 않는다. 자동 모드에서 직접 명상을 요청했다면 완료 후 기존 AI로 돌아간다. 수동 모드는 기존처럼 종료/이동 입력까지 앉아 있을 수 있다.
- 이동 입력·0.7m 초과 이동·다른 거래/행동·자동/수동 모드 변경·불 꺼짐·수면·관찰 캐릭터 변경 시 중단한다. 취소된 명상에 완료 보상을 주지 않는다.
- 기존 자동 AI의 저의지력 회복 결정/수치를 공통 표시로 연결했다. 히나의 기존 `mentalRest`는 의지력 32 미만, 38초 회복 단계, 완료 +7 및 115초 쿨다운을 유지한다. 다은의 기존 저의지력 휴식 판정과 회복률도 유지한다. 자동 휴식에 새 +6 타이머를 겹쳐 지급하지 않는다.
- 실제 등장 캐릭터는 히나·다은이다. 향후 캐릭터는 공통 레지스트리에 모닥불 및 시작/종료 어댑터를 제공할 수 있으며 새 캐릭터를 임의로 생성하지 않았다.

## 4. 선택 불빛과 물고기

- `data-selected`는 관찰/선택 캐릭터 한 명만 true이다. 채움·선택 불빛은 이 값만 사용한다. `data-auto`는 해당 캐릭터의 실제 자동 모드 값으로 독립 유지한다. 따라서 선택하지 않은 자동 캐릭터에 회전 테두리는 있을 수 있지만 선택 채움/불빛은 없다. 기존 5px·민트색·3초 회전 규격을 유지한다.
- 물고기 출현 지속 시간은 그대로 두고 **지속 시간+대기 시간 전체 주기를 1.5로 나눈다.** 대기 시간만 나누면 전체 출현율이 1.5배에 미치지 못하기 때문이다.
- 고정 난수 0.5 검증: 원래 226.875 → 새 151.25 게임 초/주기, 비율 정확히 1.5. 출현 지속 76.875초 유지, 새 대기 74.375초로 중첩 없음. 200회 반복에서도 기존 개체 35개를 재사용하고, 일일 낚시 연습 제한 4회·기존 포획/보관/굽기는 유지한다.

## 5. 검증과 제한

```sh
python3 -m http.server 8000 --bind 127.0.0.1
python3 tools/check_stabilization.py
python3 tools/check_interaction_routes.py
python3 tools/check_survival_presentation.py
```

검사는 Python Playwright와 `/usr/bin/chromium`을 사용한다. 실제 클릭을 통한 UI 열기/닫기·한 번 재생, 음원 차단, 실제 섭취 시작/완료, 명상 수치/자세/취소와 자동 회복, 실제 뱀/곰 조우의 기존 의지력 감소·쿨다운, 상호 배타 선택, 출현 주기·개체 수를 검사한다. 기존 첫날 안내·방향·테두리·꽃·대사 회귀 검사도 유지한다.

성능 수치와 해석은 [ENVIRONMENT_PROFILE.md](ENVIRONMENT_PROFILE.md), 원자료는 [ENVIRONMENT_PROFILE.json](ENVIRONMENT_PROFILE.json)에 분리했다. 그래픽 품질·꽃 개체 수는 변경하지 않았다. 실제 휴대폰 온도와 물리 GPU/열 스로틀링은 측정하지 못했으며 브라우저의 모바일 조건 검증을 실제 기기 청감/발열 검증으로 주장하지 않는다.
