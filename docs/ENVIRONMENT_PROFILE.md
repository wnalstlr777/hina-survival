# 환경 콘텐츠 렌더링 검수 — 실측 기록

## 환경과 범위

- 기준: GitHub `f02614a`의 월드/꽃/곤충 렌더링. 이 작업에서 꽃 수·형상·머티리얼·렌더링 품질을 낮추지 않았다.
- 실행: 클라우드의 headless Chromium + **SwiftShader 소프트웨어 렌더러**. PC 창과 모바일 UA/터치/창 크기 조건이며 실제 휴대폰이나 하드웨어 GPU 측정이 아니다.
- AI를 일시 정지해 장면·정오·카메라를 고정하고, 중화질에서 기존 게임 RAF와 `hinaPerformance` 샘플을 기록했다. 꽃·곤충의 원래 움직임은 해당 ON 모드에서 유지했다.
- 5개 상태별 워밍업 후 10초 기록, 전체 ON 상태 120초 추가 관찰. 별도 동일 설정 8초 재실행에서 WebGL timer query를 기록했다. 두 실행의 데이터는 JSON에서 분리했다.
- GPU 열의 값도 **소프트웨어 WebGL timer query** 경과 시간이다. 실제 휴대폰의 GPU 처리 시간/온도/전력/열 스로틀링으로 해석할 수 없다.
- 1% Low는 느린 프레임 상위 1%(최소 1개)의 평균 간격으로 계산했다. 특히 PC의 10초 샘플이 11–13프레임뿐이므로 통계적 안정성이 매우 낮다. 이 수치로 실제 기기 성능을 판단하지 않는다.

## 해석과 후속 최적화 후보

- 꽃 렌더 OFF에서 PC Draw Call은 1320→306, 모바일 조건은 약 552→178로 줄었다. 꽃은 기존 나무/수풀의 BoxGeometry 배칭 대상에서 제외되어 메시별 draw call이 남아 있다. **공유 geometry/material이 있어도 draw call 자체가 자동으로 합쳐지지는 않는다.**
- 꽃 OFF가 소프트웨어 WebGL timer 시간을 줄였으나, FPS·CPU 전체 수치는 변동이 있고 특히 PC의 첫 10초 비교에서는 개선이 일관되지 않았다. 꽃의 영향은 존재하지만 발열의 단일 원인 또는 전체 병목이라고 단정하지 않는다.
- 꽃 흔들림/곤충 CPU 비용은 이 장면에서 각각 1ms 미만이다. 현재 자료에서는 객체별 제출 비용, 전체 장면의 그림자·픽셀 처리량·오버드로우도 함께 고려해야 한다. 후자의 개별 비용은 이번 비교에서 분리 측정하지 않았다.
- 동일 꽃 형태/반응을 유지하는 material별 InstancedMesh와 거리별 CPU 업데이트 주기 조정이 후속 후보다. 이번에는 품질이나 개체 수를 임의로 낮추거나 측정되지 않은 최적화 효과를 보고하지 않는다.
- 120초 자료는 짧은 실행 추세일 뿐 실제 장시간 모바일 열 스로틀링 시험이 아니다. 실제 기기 온도, 배터리 전력, 물리 GPU 시간과 VRAM 바이트 사용량은 **미측정**이다. 메모리 표는 JS heap이며 WebGL geometry/texture 개수는 원자료에 별도 기록했다. 실제 안드로이드 기기에서 동일 카메라·밝기·해상도·충전/전원 조건으로 더 긴 비교가 필요하다.

## 재현

```sh
python3 -m http.server 8000 --bind 127.0.0.1
python3 tools/profile_environment.py --seconds 10 --steady-seconds 120 --output /tmp/environment-profile.json
```

원자료: [ENVIRONMENT_PROFILE.json](ENVIRONMENT_PROFILE.json). 모든 비교용 토글과 프로브는 테스트 응답에만 주입되며 실제 게임 기능에는 추가되지 않는다.
